# Ecosystem — вкладка достижений для набора модов

Серверный мод для **Minecraft 26.2 / Fabric**. Добавляет вкладку достижений «Экосистема»: 42 ноды, по ветке на мод.
Смысл — показать, что механики вообще существуют: достижение выдаётся тем, что ты это сделал, а в описании с юмором
сказано, чем эта штука является. Без обучающих сносок.

Мод **ничего не меняет в соседних модах и в ванильных механиках**: он только наблюдает за тем, что игрок делает
ванильными предметами, и выдаёт критерий нужного достижения. Весь текст — русский, лежит в самих файлах
достижений (клиенту ничего ставить не надо).

## Дерево

| ветка | достижения | мод |
|---|---|---|
| поле | Комбайн · Целина · Сеятель | `hoefarm` |
| котёл | Стирка · Химчистка | `cauldronwash` |
| лестницы | Верёвка · Тарзан | `ladderhang` |
| вагонетки | Экспресс · Газ в пол · Сороковка · С путей долой | `fastminecarts` |
| ПВО | ПВО · Захват · В яблочко | `pvo` |
| варп | Якорь · Пара · Прыжок · Туда и обратно | `lodestonewarps` |
| стол | Стол · Сокровище | `enchantxp` + `enchantqol` |
| лошади | Рысак · Кавалерия · Рог-поводок · Свистни | `steed` |
| дальние земли | Дальний поход · Глушь · Трофей · Сюрприз | `mobscaler` |
| рамки | Призрак · Явление · Надпись · Возврат | `ghostframe` |
| лук | Лучник · Своя стрела · Снайпер | `fletcher` |
| рыбалка | Подсечка · Чистый бой · Живая рыба · Трофей · Под землёй клюёт | `brine` |
| финал | **Свояк** — по одному трюку каждого мода | все |

Ноды ветки — разные действия, а не пороги одного и того же: сбор / вспашка / посев, ткань / стекло, короткая
верёвка / шестнадцать метров, скорость 20 / 35 / 38 б/с с выдержкой 2 / 5 / 10 секунд, дойти 3000 / дойти 12000 /
убить / поймать стрелу, спрятать рамку / вернуть / спрятать табличку / вернуть текст, открыть стол / собрать
стрелу / убить ею. Одно нажатие не выдаёт два достижения.

Дерево двухуровневое: «голова» ветки и её дети («Лучник» → «Своя стрела», «Комбайн» → «Целина»). Глубже нельзя:
сервер присылает незаработанную ноду, только если завершена она сама, родитель или дед
(`AdvancementVisibilityEvaluator`: стек предзаполнен тремя `NO_CHANGE`, проверяются `peek(0..2)`; корень завершён
на входе) — то есть на глубине 3 от корня нода видна лишь после получения родителя. Это правило, а не запрет:
`check-eco-data.ps1` ругается на глубину > 2, чтобы вкладка не показывала пустые места.

Родитель в дереве — это «чей это трюк», а не условие: ванильные достижения не требуют закрытого предка. Поэтому
«Кавалерия» (зачарование конской брони) висит под «Рысаком» — это тот же мод про лошадей, а не шаг после езды.
Прямые дети корня — ровно головы веток и «Свояк»; всё остальное висит на своей голове, иначе вкладка рассыпается
в сетку одинаковых иконок.

Ванильные триггеры там, где они бесплатны: `enchanted_item` (стол, броня лошади, сокровища), `started_riding`
(лошадь), `tick` (корень → вкладка появляется на первом входе). Остальные критерии — `minecraft:impossible`,
мод выдаёт их через `PlayerAdvancements#award`; тосты, чат и дерево штатные.

## Как мод видит механику соседа

| что | как ловится |
|---|---|
| поле | снимок блока-цели на входе пакета `handleUseItemOn`, сравнение 5×5×3 следующим тиком: спелая культура → собрано, земля → вспахано, воздух → посажено |
| котёл | тот же снимок: предмет в руке сменился у водяного котла; семейство выводится из имени нового предмета |
| лестница | тот же снимок: под низом цепочки появилась лестница, длина считается по цепочке |
| вагонетки | раз в 5 тиков: скорость вагонетки с игроком (`deltaMovement × 20`) и сколько тиков она держится; отброс — живой моб рядом с быстрой вагонеткой |
| ПВО | ракета из арбалета запоминается при загрузке; разворот > 20° = захват, взрыв такой ракеты по живому = попадание |
| варп | раз в 10 тиков: блеск на компасе восстановления = якорь; блеск снят у лодстоуна = пара; прыжок > 64 блоков у лодстоуна = телепорт, второй в пределах 10 минут = «туда и обратно» |
| лошади | `UseEntityCallback` (рогом по лошади) и `UseItemCallback` + реальное появление лошади рядом (вызов); привязка читается из `custom_data.steed` |
| дальние земли | опрос расстояния от центра раз в 10 тиков (3000 — старт усиления, 12000 — «Глушь»); смерть по тегу `mobscaler:scaled`; стрела, чей хозяин — скелет с тегом `mobscaler:arrow:*` |
| рамки | сущность — `handleInteract` + `ItemFrame#isInvisible` следующим тиком; табличка — `handleUseItemOn`/`handlePlayerAction` по маркеру и проверка, что на месте таблички появился `structure_void` (или наоборот). В ghostframe 1.3 у стены текст ложится граффити на стену, у столба висит, но маркер тот же |
| лук | клик по столу лучника откладывается на тик и засчитывается по реально открытому меню (`containerMenu != inventoryMenu`), а не по пакету: ваниль проверяет дистанцию уже после него. Своя стрела — опрос инвентаря на `minecraft:arrow` с `custom_data.fletcher`, убийство — `AFTER_DEATH` с этой стрелой в `direct_entity` |
| рыбалка | `brine` ставит на игрока ванильные теги сущности (`brine:caught`, `perfect`, `cave`, `live`, `trophy` через `Entity#addTag`); раз в секунду читаются `entityTags()` и выдаются ноды. Теги — только сервер и NBT игрока, клиенту ничего не уходит и он об этом не знает; своей статистики (`Stats.CUSTOM`) нет намеренно: её реестр клиенту не синхронизируется и `award_stats` разорвал бы соединение. Своих API и зависимости на сборке тоже нет; без `brine` ветка не выдаётся и «Свояк» её не ждёт (`Ecosystem.BRINE_LOADED`) |

Совместимость проверена с `ghostframe 1.3.0` (граффити на стене, яркие чернила), `fletcher 1.2.2`
(спец-стрелы: огонь, свечение, планирование, отбрасывание; стол открывается и с шифтом, если в руке не блок) и
`brine 1.0.0` (теги улова).

Без `brine` ветка рыбалки не выдаётся и в «Свояке» не участвует (`Ecosystem.BRINE_LOADED`), как и ветка лука без
`fletcher`: иначе капстоун стал бы недостижим навсегда.

## Оптимизация

- Один обработчик конца тика; в простое он не выделяет ничего (пустые коллекции), вагонетки опрашиваются раз в
  5 тиков, варп — раз в 10, инвентарь на стрелы — раз в 20.
- 150 чтений блоков бывает только по клику мотыгой/лестницей/котлом, сущность рамки — только по клику мембраной.
- В реестрах игры не регистрируется ничего: ни предметов, ни блоков, ни пакетов, ни сущностей.

Отладка: `-Decosystem.debug=true` — в лог пишется каждое выданное достижение.

## Проверено

- `gradlew build` — jar `build/libs/ecosystem-1.1.1.jar`.
- Копия сервера (`D:\Temp\serv-eco`, плоский мир, полный набор модов + `ghostframe 1.3.0`, `fletcher 1.2.2`,
  `brine 1.0.0`): мод грузится, миксины применяются, `Loaded 1797 advancements` (+5 нод рыбалки), самопроверка
  **`Ecosystem: вкладка цела — нод: 42, веток «Свояка»: 12`**, ошибок разбора и валидации нет.
- Инварианты данных проверяются скриптом `C:\Temp\opencode\check-eco-data.ps1`: 42 файла, один корень, нет циклов,
  `parent` существует, глубина ≤ 2, у всех выдаваемых кодом нод критерий `code`, `requirements` покрывают все
  критерии, `background` только у корня, BOM нет, а списки id и веток сверяются с `Awards.IDS`/`BRANCHES` из
  `Awards.java` (переименование в коде скрипт больше не пропускает). Там же сверяется контракт с рыбалкой: пять
  строк тегов из `brine/Marks.java` против тех, что читает `Fishing.java`, и что каждая выдаваемая нода есть в `IDS`.
- Неизвестный id иконки или предмета в критерии роняет загрузку всего файла — это видно на старте как
  `Ecosystem: не загружено …: <id>(нет)`; статически по jar такие id не проверяются (блочные варианты вроде
  `white_stained_glass_pane` не имеют отдельного поля).
- «Свояк» проверяется в миксине на `PlayerAdvancements#award` (RETURN, только при `true`): через этот метод
  проходит и наша выдача, и ванильные триггеры, поэтому последняя закрытая ветка на `enchanted_item` или
  `started_riding` выдаёт капстоун сразу, без опроса игроков в тике. Выдача самого «Свояка» проверку не
  запускает — иначе была бы рекурсия.
- Без мода `fletcher` (`Ecosystem.FLETCHER_LOADED = false`) ветка лука не учитывается в капстоуне: иначе
  «Свояк» был бы недостижим навсегда, а тик молча ждал бы несуществующий стол. Мод добавлен в `recommends`.
  Так же и без `brine` (`BRINE_LOADED`) — ветка рыбалки.
- Теги улова переживают смерть и рестарт: `PlayerList#respawn` явно переносит `entityTags()` в нового игрока,
  а `Entity#saveWithoutId` пишет их в `Tags` playerdata. Поэтому выдача не теряется, даже если игрок умер
  в ту же секунду, что поймал рыбу.
- Игровая проверка (клик, тост, вкладка) — за владельцем: без клиента это не проверить.

## Как добавить достижение

1. Строка в таблице `C:\Temp\opencode\gen-ecosystem.ps1` (генератор, не часть мода) → `pwsh -File` — он разложит
   `data/ecosystem/advancement/<id>.json`. Кавычки в текстах — только «», иначе JSON поедет.
2. Константа и путь в `Awards` + вызов `Awards.award(player, id)` из нужного детектора.
3. Если нода — первая в ветке, добавить её в `Awards.BRANCHES` (из них собирается «Свояк»).
