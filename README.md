# Ecosystem — вкладка достижений для набора модов

Серверный мод для **Minecraft 26.2 / Fabric**. Добавляет вкладку достижений «Экосистема»: 48 нод, по ветке на мод.
Смысл — показать, что механики вообще существуют: достижение выдаётся тем, что ты это сделал, а в описании с юмором
сказано, чем эта штука является. Без обучающих сносок.

Мод **ничего не меняет в соседних модах и в ванильных механиках**: он только наблюдает за тем, что игрок делает
ванильными предметами, и выдаёт критерий нужного достижения. Весь текст — русский, лежит в самих файлах
достижений (клиенту ничего ставить не надо).

## Дерево

Цепочка читается как «сначала это, потом то», но родитель — это **чей это трюк**, а не жёсткое условие:
ванильные достижения не требуют закрытого предка. Поэтому листья висят под тем шагом, без которого действие
физически не бывает (нельзя убить стрелой со стола, не сделав стрелу).

| ветка | цепочка | мод |
|---|---|---|
| поле | Комбайн → Целина, Сеятель | `hoefarm` |
| котёл | Стирка → Химчистка | `cauldronwash` |
| лестницы | Верёвка → Тарзан | `ladderhang` |
| вагонетки | Экспресс → Газ в пол → **Сороковка**; С путей долой | `fastminecarts` |
| ПВО | ПВО → Захват → **В яблочко** | `pvo` |
| варп | Якорь → Прыжок → **Туда и обратно**; Пара | `lodestonewarps` |
| стол | Стол → **Сокровище** | `enchantxp` + `enchantqol` |
| лошади | Рысак → Рог-поводок → **Свистни**; Кавалерия | `steed` |
| дальние земли | Дальний поход → Глушь → **Край света**; Трофей, Сюрприз | `mobscaler` |
| рамки | Призрак → Надпись → **Возврат**; Явление | `ghostframe` |
| лук | Лучник → Своя стрела → **Снайпер** → **Порох**; Колчан, Взлом | `fletcher` |
| рыбалка | Подсечка → Живая рыба → **Трофей**; Чистый бой, Под землёй клюёт, Гроза, Крупная дичь | `brine` |
| финал | **Свояк** — по одному трюку каждого мода, включая чужую вкладку `anomaly` | все |

Ноды ветки — разные действия, а не пороги одного и того же: сбор / вспашка / посев, ткань / стекло, короткая
верёвка / шестнадцать метров, скорость 20 / 35 / 38 б/с с выдержкой 2 / 5 / 10 секунд, дойти 3000 / дойти 12000 /
дойти до границы / убить / поймать стрелу, спрятать рамку / вернуть / спрятать табличку / вернуть текст, открыть
стол / собрать стрелу / сделать колчан / разбить блок стрелой / убить / взорвать. Одно нажатие не выдаёт два
достижения.

Дерево вложенное, до четырёх шагов от корня (раньше было два — владелец разрешил длиннее, до десяти).
Нода глубже второго уровня приходит клиенту только после получения родителя: сервер шлёт незаработанную ноду,
если в окне из трёх предков есть завершённая (`AdvancementVisibilityEvaluator`: стек предзаполнен тремя
`NO_CHANGE`, проверяются `peek(0..2)`; корень завершён на входе). Это правило, а не запрет: скрипт
`check-eco-data.ps1` ругается только на глубину больше десяти.

Прямые дети корня — ровно головы веток и «Свояк»; всё остальное висит в своей ветке, иначе вкладка рассыпается
в сетку одинаковых иконок.

Ванильные триггеры там, где они бесплатны: `enchanted_item` (стол, броня лошади, сокровища), `started_riding`
(лошадь), `tick` (корень → вкладка появляется на первом входе). Остальные критерии — `minecraft:impossible`,
мод выдаёт их через `PlayerAdvancements#award`; тосты, чат и дерево штатные.

## Как мод видит механику соседа

| что | как ловится |
|---|---|
| поле | снимок блока-цели на входе пакета `handleUseItemOn`, сравнение 5×5×3 следующим тиком: спелая культура → собрано, земля → вспахано, воздух → посажено |
| котёл | тот же снимок: предмет в руке сменился у водяного котла; семейство выводится из имени нового предмета |
| лестница | тот же снимок: под низом цепочки появилась лестница, длина считается по цепочке |
| вагонетки | раз в 5 тиков: скорость вагонетки с игроком (`deltaMovement × 20`) и сколько тиков она держится; отброс — живой моб рядом с быстрой вагонеткой |
| ПВО | ракета из арбалета запоминается при загрузке; разворот > 20° = захват, взрыв такой ракеты по живому = попадание |
| варп | раз в 10 тиков: блеск на компасе восстановления = якорь; блеск снят у лодстоуна = пара; прыжок > 64 блоков у лодстоуна = телепорт, второй в пределах 10 минут = «туда и обратно» |
| лошади | `UseEntityCallback` (рогом по лошади) и `UseItemCallback` + реальное появление лошади рядом (вызов); привязка читается из `custom_data.steed` |
| дальние земли | опрос расстояния от центра раз в 10 тиков (3000 — старт усиления, 12000 — «Глушь»); «Край света» — километр до границы мира, расстояние считается по квадрату границы (максимум по осям, а не гипотенуза), а порог берётся из `WorldBorder` каждого измерения, а не из константы; смерть по тегу `mobscaler:scaled`; стрела, чей хозяин — скелет с тегом `mobscaler:arrow:*` |
| рамки | сущность — `handleInteract` + `ItemFrame#isInvisible` следующим тиком; табличка — `handleUseItemOn`/`handlePlayerAction` по маркеру и проверка, что на месте таблички появился `structure_void` (или наоборот). В ghostframe 1.3 у стены текст ложится граффити на стену, у столба висит, но маркер тот же |
| лук | клик по столу откладывается на тик и засчитывается по реально открытому меню (`containerMenu != inventoryMenu`). Своя стрела — опрос инвентаря на `minecraft:arrow` с `custom_data.fletcher`. Колчан — снимок руки: был пустой мешок, стал мешок с `custom_data.fletcher_quiver.quiver` (колчан, который уже был в руке, ничего не превращает). Убийство — `AFTER_DEATH` с этой стрелой в `direct_entity`; стрела с `custom_data.fletcher.explode` даёт ещё и «Порох». Взлом — `PlayerBlockBreakEvents.AFTER` плюс проверка, что рядом стрела с `custom_data.fletcher.break`, которая **только что воткнулась** (флаг `inGround` через аксессор-миксин, плюс движение за прошлый тик): пролетающая мимо или давно стоящая в блоке не считается |
| рыбалка | `brine` ставит на игрока ванильные теги сущности (`brine:caught`, `perfect`, `cave`, `live`, `trophy`, `storm`, `beast` через `Entity#addTag`); раз в секунду читаются `entityTags()` и выдаются ноды. Теги — только сервер и NBT игрока, клиенту ничего не уходит и он об этом не знает; своей статистики (`Stats.CUSTOM`) нет намеренно: её реестр клиенту не синхронизируется и `award_stats` разорвал бы соединение. Своих API и зависимости на сборке тоже нет; без `brine` ветка не выдаётся и «Свояк» её не ждёт (`Ecosystem.BRINE_LOADED`) |

Совместимость проверена с `ghostframe 1.3.0` (граффити на стене, яркие чернила), `fletcher 1.6.2` (колчан в мешке,
железная стрела ломает блок, порох взрывается, старые спец-стрелы без новых ключей читаются как обычные),
`brine 1.0.0` (все семь тегов улова), `mobscaler 2.2.0` (граница 20000 в каждом измерении) и
`anomaly 0.3.0` (её собственное достижение «Выжил»).

Без `brine` ветка рыбалки не выдаётся и в «Свояке» не участвует (`Ecosystem.BRINE_LOADED`), как и ветка лука без
`fletcher`: иначе капстоун стал бы недостижим навсегда. То же правило теперь для **любой** ветки: таблица
`Awards.BRANCH_MODS` связывает ветку с модом, и «Свояк» ждёт только те ветки, чьи моды стоят на сервере (скрипт
сверяет пары с `BRANCHES` и с `recommends`). Если не стоит ни один мод набора, капстоун не выдаётся вовсе —
пустая награда за вход никому не нужна.

`anomaly` держит свою вкладку и свою выдачу, поэтому ecosystem не дублирует его ноды: «Свояк» читает из общего
реестра достижений готовое `anomaly:survived` (`Awards.ANOMALY_NS/ANOMALY_PATH`) и не ждёт его, если мода нет
(`Ecosystem.ANOMALY_LOADED`). Связь — по id данных, а не по классам: сборка от `anomaly` не зависит.

## Оптимизация

- Один обработчик конца тика; в простое он не выделяет ничего (пустые коллекции), вагонетки опрашиваются раз в
  5 тиков, варп — раз в 10, инвентарь на стрелы — раз в 20.
- 150 чтений блоков бывает только по клику мотыгой/лестницей/котлом, сущность рамки — только по клику мембраной.
- Ломающие стрелы в полёте отслеживаются картой по UUID (их единицы); запись снимается в том же тике, в котором
  стрела исчезла, и при остановке сервера.
- В реестрах игры не регистрируется ничего: ни предметов, ни блоков, ни пакетов, ни сущностей.

Отладка: `-Decosystem.debug=true` — в лог пишется каждое выданное достижение.

## Проверено

- `gradlew build` — jar `build/libs/ecosystem-1.2.0.jar`.
- Копия сервера (`D:\Temp\serv-eco`, плоский мир, полный набор модов + `ghostframe 1.3.0`, `fletcher 1.6.2`,
  `brine 1.0.0`, `anomaly 0.3.0`): мод грузится, миксины применяются, `Loaded 1807 advancements` (+6 нод набора
  и +4 ноды anomaly), самопроверка **`Ecosystem: вкладка цела — нод: 48, веток «Свояка»: 12, +anomaly:survived`**,
  ошибок разбора и валидации нет.
- Инварианты данных проверяются скриптом `C:\Temp\opencode\check-eco-data.ps1`: 48 файлов, один корень, нет циклов,
  `parent` существует, глубина ≤ 10, у всех выдаваемых кодом нод критерий `code`, `requirements` покрывают все
  критерии, `background` только у корня, BOM нет, а списки id и веток сверяются с `Awards.IDS`/`BRANCHES` из
  `Awards.java`. Там же сверяется контракт с рыбалкой (семь строк тегов из `brine/Marks.java` против тех, что
  читает `Fishing.java`), что каждый `Awards.X`, упомянутый в любом файле мода, входит в `IDS`, что пары
  `Awards.BRANCH_MODS` совпадают с `BRANCHES` и есть в `recommends`, и что `anomaly:<path>` из `Awards`
  действительно существует в `anomaly`-репозитории.
- Неизвестный id иконки или предмета в критерии роняет загрузку всего файла — это видно на старте как
  `Ecosystem: не загружено …: <id>(нет)`; статически по jar такие id не проверяются.
- «Свояк» проверяется в миксине на `PlayerAdvancements#award` (RETURN, только при `true`): через этот метод
  проходит и наша выдача, и ванильные триггеры, и чужая нода anomaly, поэтому последняя закрытая ветка на
  `enchanted_item`, `started_riding` или `anomaly:survived` выдаёт капстоун сразу, без опроса игроков в тике.
  Выдача самого «Свояка» проверку не запускает — иначе была бы рекурсия.
- Без мода `fletcher` (`Ecosystem.FLETCHER_LOADED = false`) ветка лука не учитывается в капстоуне, так же без
  `brine` и без `anomaly`: мод добавлен в `recommends`.
- Теги улова переживают смерть и рестарт: `PlayerList#respawn` явно переносит `entityTags()` в нового игрока,
  а `Entity#saveWithoutId` пишет их в `Tags` playerdata.
- Игровая проверка (клик, тост, вкладка, колчан, взлом стрелой, взрыв) — за владельцем: без клиента это не проверить.

## Как добавить достижение

1. Строка в таблице `C:\Temp\opencode\gen-ecosystem.ps1` (генератор, не часть мода) → `pwsh -File` — он разложит
   `data/ecosystem/advancement/<id>.json`. Кавычки в текстах — только «», иначе JSON поедет.
2. Константа и путь в `Awards` + вызов `Awards.award(player, id)` из нужного детектора.
3. Если нода — первая в ветке, добавить её в `Awards.BRANCHES` (из них собирается «Свояк»).
